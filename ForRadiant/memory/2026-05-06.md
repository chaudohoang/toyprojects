# 2026-05-06 — FTPUploaderVB C# Conversion

## What We Did

- Studied `FTPUploaderVB`, a VB.NET WinForms automatic FTP upload queue processor.
- Confirmed behavior:
  - polls `D:\Program\RVS\UploadQueue` by default
  - reads positional queue `.txt` files
  - uploads files through `WinSCPnet.dll` and a queue-provided WinSCP executable path
  - updates success/fail logs, summary CSV, fail-count files, index/host files
  - deletes or optionally backs up queue files after success/max retry
  - supports tray minimize and single-instance behavior
- Created new `FTPUploaderCS` project beside the VB project.
- Added `FTPUploaderCS` to `ForRadiant.sln`.

## New Project

`FTPUploaderCS` is a classic C# WinForms project targeting `.NET Framework 4.8`.

The UI is code-only in `MainForm.cs`; there is no Designer file.

Main structure:

- `Models/UploadQueueItem.cs` — explicit model for the 17-line queue format.
- `Models/UploadSettings.cs` — queue path, interval, max uploads, max retries, backup option.
- `Services/QueueFileParser.cs` — parses positional queue files.
- `Services/FtpUploadService.cs` — wraps WinSCP FTP upload.
- `Services/UploadWorker.cs` — background polling and upload orchestration.
- `Services/RetryTracker.cs` — fail-count files.
- `Services/QueueBackupService.cs` — queue backup copies.
- `Services/SummaryLogUpdater.cs` — summary CSV O/X updates.
- `Infrastructure/NativeMethods.cs` — single-instance window message support.

## Verification

Attempted:

```powershell
dotnet build FTPUploaderCS\FTPUploaderCS.csproj -v:minimal
```

Result: build could not compile in this sandbox because the machine lacked .NET Framework 4.7.2 reference assemblies / targeting pack at that time:

```text
MSB3644: The reference assemblies for .NETFramework,Version=v4.7.2 were not found.
```

The user then installed the .NET Framework 4.8 Developer Pack and `FTPUploaderCS` was retargeted to .NET Framework 4.8.

After retargeting, `dotnet build FTPUploaderCS\FTPUploaderCS.csproj -v:minimal` compiled the C# code successfully. The first .NET 4.8 build failed only because the copied post-build cleanup used `$(SolutionDir)`, which is undefined for direct project builds. The post-build cleanup was changed to use `$(TargetDir)`.

Current verification result:

